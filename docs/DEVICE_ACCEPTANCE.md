# 观象·命盘 — Web / iPhone 文件流验收清单

> 适用批次：Phase 3 P3-F  
> 文件流范围：普通 JSON 备份、密码保护加密备份、导入预览、合并/替换恢复  
> 数据边界：文件由用户主动选择保存或分享，应用不会把命盘上传到服务端。

## 已落地的文件流

| 场景 | 实现 | 结果 |
|---|---|---|
| Web 导出普通备份 | `Blob` + 隐藏下载链接 | 下载 `guanxiang-backup-<UTC>.json` |
| Web 导出加密备份 | `Blob` + 隐藏下载链接 | 下载 `guanxiang-encrypted-backup-<UTC>.json` |
| Web 导入 | `expo-document-picker`；优先读取 `asset.file`，否则读取 blob URI | 解析前不写本机 |
| iPhone 导出 | 临时目录写 UTF-8 JSON + `expo-sharing` | 通过系统分享面板保存到“文件”或发送到用户选择的目标 |
| iPhone 导入 | `expo-document-picker` 复制到缓存目录 + UTF-8 读取 | 解析前不写本机 |
| 导入冲突 | 预览重复的命主/记录 ID | 合并默认保留本机；替换使用文件版本 |
| 恢复失败 | 多 key 事务写入 + 精确旧值回滚 | 注入写入失败时旧数据保持不变 |

文件名只含产品名、备份类型和 UTC 时间，不包含手机号、命主姓名或记录内容。加密备份的密码不写入文件名、备份正文或本机状态。

## 自动化证据

在仓库根目录执行：

```bash
npm run typecheck
npm run lint
npm test
npm run build:web
```

P3-F 的文件名契约和 Web/iPhone 共用 MIME 类型由 `tests/backup-file-contract.regression.mjs` 覆盖；导入冲突与事务回滚由 `tests/import-plan.regression.mjs` 覆盖。CI 会执行同一组检查，并且 Web Export 使用 `always()`，不会因为前面的测试失败而跳过。

## 手工验收矩阵

### Web（Chrome / Edge）

- [ ] 设置页导出普通备份，浏览器下载目录出现 `.json` 文件；文件可用文本编辑器打开并包含 `guanxiang-local-backup`。
- [ ] 导出加密备份，文件正文不出现命主姓名；输入少于 8 位密码时操作被拒绝。
- [ ] 选择普通备份后，先看到当前/文件的命主、记录、反馈和八字深度快照计数；取消不会改变本机数据。
- [ ] 对存在重复 ID 的文件分别选择“合并导入”和“替换本机”，结果符合预览说明。
- [ ] 选择错误 JSON、错误密码和篡改后的加密文件，页面显示错误且原始本机资料仍可打开。
- [ ] 浏览器刷新后，恢复后的命主、记录、收藏和事实反馈仍在本机。

### iPhone（iOS 文件 App）

- [ ] 导出普通备份，在系统分享面板选择“存储到文件”，重新选择该文件可以恢复。
- [ ] 导出加密备份，在“文件”中确认文件与密码分开保存；错误密码不会覆盖本机数据。
- [ ] 从“文件”选择器导入普通/加密备份；取消选择不会改变本机数据。
- [ ] 在重复 ID 场景核对合并/替换结果；恢复过程中故意制造写入失败时，旧数据仍可读取。
- [ ] 在系统设置打开“减少动态效果”后，备份页面仍可操作，导入预览不依赖动画完成。

## 当前状态与阻塞项

- Web 静态构建和自动化回归可在 Windows 环境完成。
- iPhone 真机需要 macOS/Xcode 或 TestFlight 包；当前仓库已完成原生文件流实现和验收清单，但尚未声称完成实体 iPhone 的最终签字。
- 在实体设备签字前，不对外承诺“跨设备自动同步”；本批次仍是用户主动导出、主动分享、主动导入。
